# Building and testing on Windows

Use an x64 Windows machine with Developer Mode enabled and a short writable checkout path. The source includes Android and Windows native projects; do not run `flutter create .` over them. No signing secrets, personal app data, Gemini key, or connected device is needed for host tests and dev builds.

## Toolchain

Exact tested versions are in [`toolchain.json`](../toolchain.json): Flutter 3.47.7/Dart 3.13.5, Rust 1.98.1, Python 3.14.7, PowerShell 7.6.5, Git 2.53.0.windows.3, Java 25.0.3, Android platform 37 revision 2, build-tools 36.0.0, NDK 30.0.16248370, Android CMake 3.22.1, and Visual Studio Build Tools 2026 with Desktop development with C++, MSVC 14.51.36231 and Windows SDK 10.0.22621.0. Android Studio supplies Java; Visual Studio supplies Windows CMake/Ninja. Gradle 9.3.1, AGP 9.1.0 and Kotlin 2.4.20 are project-pinned.

Download tools from [Flutter](https://docs.flutter.dev/install/archive), [Rust](https://rustup.rs), [Android Studio](https://developer.android.com/studio), [Visual Studio](https://visualstudio.microsoft.com/downloads/), [Python](https://www.python.org/downloads/), [PowerShell](https://github.com/PowerShell/PowerShell/releases) and [Git for Windows](https://gitforwindows.org/). Match `toolchain.json`; do not silently replace unavailable pins with newer tools.

Put Flutter in a sibling `cookdex-tools/flutter` directory. Android Studio/SDK and Visual Studio may use their standard installer locations. Add Git, PowerShell, Python to PATH. `env.ps1` derives paths; override `COOKDEX_TOOLS`, `FLUTTER_SDK`, `PUB_CACHE`, `CARGO_HOME`, `GRADLE_USER_HOME`, `JAVA_HOME` or `ANDROID_HOME` if needed. Paths written as `<path>` in documentation are placeholders.

In PowerShell 7, from the repository root:

```powershell
rustup toolchain install 1.98.1 --profile default --component rustfmt --component clippy --target aarch64-linux-android --target x86_64-linux-android
. ./flutter/scripts/env.ps1
& (Join-Path $env:ANDROID_HOME 'cmdline-tools/latest/bin/sdkmanager.bat') 'platform-tools' 'platforms;android-37.0' 'build-tools;36.0.0' 'ndk;30.0.16248370' 'cmake;3.22.1'
& (Join-Path $env:ANDROID_HOME 'cmdline-tools/latest/bin/sdkmanager.bat') --licenses
flutter config --enable-windows-desktop
flutter precache --android --windows
cargo fetch --manifest-path flutter/rust/Cargo.toml --locked
Push-Location flutter
flutter pub get --enforce-lockfile
Pop-Location
./scripts/install-gitleaks.ps1
./scripts/doctor.ps1
```

Review vendor licenses yourself. SDK Manager can select a newer package revision; doctor detects mismatches. Gitleaks installation verifies a pinned official archive checksum. Doctor reads metadata/version output and never opens signing files or connects to a device. Build wrappers use offline Cargo/pub once caches are populated; Gradle may download pinned dependencies on first use.

## Dev builds

```powershell
./flutter/scripts/build.ps1 -Platform android -Mode release -StandardDebugKey
./flutter/scripts/build.ps1 -Platform windows -Mode release
```

The APK is `flutter/build/app/outputs/flutter-apk/app-release.apk` (ARM64 only). The Windows executable and adjacent required files are in `flutter/build/windows/x64/runner/Release`. Keep that directory together. Dev builds use separate data and sync identity from production. Android reuses an existing sibling `cookdex-secrets/android/recipe-debug.keystore` if present; otherwise it uses the standard debug certificate generated by Gradle. An explicit `RECIPE_DEBUG_KEYSTORE` may select your own dev key, but a missing explicit key is an error. `-StandardDebugKey` skips both the existing-key lookup and that override. Production never falls back to debug signing and requires the maintainer's separate signing configuration.

Build commands do not install apps. To try a dev build, open the APK on your own test device or run the dev executable yourself. Never use a personal recipe library as test data. A changed signing certificate cannot update an existing installation in place; use a separate test environment and preserve your backups.

## Host verification

```powershell
./flutter/scripts/test.ps1
./flutter/scripts/verify-zip.ps1
python -m unittest discover -s flutter/scripts -p 'test_*.py'
./flutter/scripts/build.ps1 -Platform android -Mode release -StandardDebugKey
Push-Location flutter/android
./gradlew.bat :app:testDebugUnitTest '-Ptarget-platform=android-arm64'
Pop-Location
```

The full host wrapper runs Rust formatting/tests, Flutter analysis/tests, disposable signing-tool tests, three Windows fixture integrations and native HTTP tests. Tests launch only synthetic fixture entry points. `-SkipWindowsNative` runs the smaller host subset. Screenshot tests are opt-in and some tests need `FLUTTER_SDK` to load fonts; the environment script sets it. Python tests validate synthetic trace-analysis helpers. ZIP verification generates synthetic archives and checks old formats, corruption, ranges and shopping setup. No automated test calls Gemini.

Generated Gradle wrappers, native libraries, plugin links and build caches are recreated from source and dependencies. Keep generated output out of Git. Test-only native probe libraries must never ship.

## Changing the bridge

Ordinary builds use the committed bindings. For API changes, install `flutter_rust_bridge_codegen` 2.13.0 in the tools directory and `cargo-expand` 1.0.126, then run `flutter/scripts/generate-bridge.ps1`. Update tests and format the generated changes before submitting a pull request.
